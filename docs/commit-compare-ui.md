# 커밋 대조 UI/UX · 2026-11-02

## 실제 연동 단계 · 최신 상태

아래 UI 우선 기록은 당시 이력이다. 현재는 `CommitCompare`가 데모의 `CommitPreview`와 실무의 `LiveCommitCompare`를 분리해 제공한다.

- 사용자별 GitHub OAuth 연결/해제, 고객사별 여러 저장소 등록/해제(관리자), 브랜치 조회·대조, 변경 파일/패치와 수동 대응 저장/해제를 구현했다. 기존 요청과 배포 반영일은 변경하지 않는다.
- GitHub 호출은 Supabase `github` Edge Function으로 수행한다. TGS 활성 계정·고객사 권한·GitHub 접근 권한을 검사하고 토큰과 임시 인증 코드는 사용자에 묶어 AES-GCM으로 암호화한다. 브라우저에는 GitHub 토큰을 저장하지 않는다.
- OAuth 콜백 이후에도 연결을 시작한 TGS 계정의 일회성 완료 요청을 요구한다. 계정/고객사 변경 중 확인창과 늦은 조회 응답은 취소하며 다른 계정의 인증으로 실행하지 않는다.
- 기준 최대 500건, 대상 최대 1000건과 파일 최대 300개의 조회 범위를 표시한다. 불완전한 탐색에서 대응을 못 찾으면 검토 필요로 남긴다. 과거 수동 대응이 늘어도 현재 기준 SHA별로 나눠 조회한다.
- 일반 오류는 기존 결과를 유지하고 복구를 안내한다. 인증·권한 오류는 비공개 결과를 숨긴다. 비활성 고객사는 선택할 수 없으며 연결 상태 조회 실패와 로딩을 구분한다.
- 검증: 단위/DB 49개, 브라우저 전체 71개, TypeScript 포함 일반/데모 빌드 및 Deno 함수 검사 통과. 실제 외부 인증·고객사 저장소 대신 합성 HTTP 응답을 사용했다. 일반 빌드는 기존과 같이 큰 번들 경고가 있다.
- 1440/768/390px 결과·변경 파일 화면 6개를 `.impeccable/review/github-live/`에서 확인했다. 페이지 가로 넘침 없음. 디자인 탐지 1회 결과 `work/github-live-detect.json`은 `[]`이다. 별도 마무리 UI 리뷰 판정은 `ship`, 수정할 주요 사항 없음이다.
- 실제 프로젝트 마이그레이션·함수 배포·비밀 설정은 수행하지 않았다. GitHub OAuth App 등록 후 [설정 가이드](github-setup.md)에 따라 연결하고 실제 비공개 저장소로 최종 확인해야 한다. 커밋·push·클라우드 배포는 하지 않았다.

- Mode: Operate. 승인된 작업은 기존 요청 관리와 독립적인 커밋 대조 화면의 UI 우선 구현이다. 실제 OAuth·GitHub API·토큰 저장·DB 변경은 다음 단계다.
- 기존 브랜드·사이드바·서체·폼·상태 색상 체계를 계승한다. 논의된 구성은 연결 안내 → 저장소/브랜치/기간 조건 → 커밋 대조 표 → 대응 근거 패널이다. 새 시각 세계나 장식적인 요약 카드 묶음을 만들지 않는다.
- /#/commits 경로를 업무 메뉴와 모바일 메뉴에 추가한다. 공개 데모에서는 가상 결과를 바로 확인하고, 실무 화면에서는 연결 전 안내와 가상 미리보기 진입을 제공한다. 모든 화면에 실제 연동이 아닌 가상 데이터임을 명시한다.
- 가상 저장소 여러 개, 동일 SHA·체리픽 출처·미확인·후보 검토·수동 대응 사례를 제공한다. 대조 결과는 서버 배포 여부를 뜻하지 않는다. 기간은 기준 커밋 범위이며 대상 브랜치 탐색 범위·기준 SHA를 결과에 명시한다.
- 비교 조건은 변경 후 대조하기를 눌러 적용한다. 결과 검색·분류·행 선택·변경 파일 보기·가상 수동 연결/해제를 동작하게 한다. 수동 연결은 현재 화면 메모리에만 있고 새로고침 시 초기화된다.
- PC에서는 표와 근거 패널을 나란히, 좁은 화면에서는 표 대신 읽기 쉬운 세로 행을 사용하고 선택 시 상세를 표시한다. 닫기/Escape/뒤로 버튼은 목록과 키보드 초점으로 돌아온다.
- 일시 조회 실패는 이전 결과를 유지하고 마지막 조회 정보와 재시도를 표시한다. 인증 만료·권한 부족은 결과를 숨기고 필요한 조치를 안내한다. 연결 전·불러오는 중·빈 결과·검색 결과 없음도 구분한다.
- 검증: 데모/실무 진입, 비교 조건 적용, 검색/분류, 대응 근거/가상 연결, 오류 상태, PC/태블릿/모바일 넘침·초점 및 기존 화면 회귀. 실제 외부 인증이나 회사 저장소 호출은 하지 않는다.

## UI 우선 단계 완료 기록

- 구현: `src/features/commits/CommitCompare.tsx`, `preview.ts`, `commits.css`. `src/app/App.tsx`의 업무/모바일 메뉴와 `/#/commits` 경로로 진입한다. 데모에서는 결과, 실무 모드에서는 연결 전 안내로 시작하며 가상 미리보기를 열 수 있다.
- 고객사·저장소·기준/대상 브랜치·기간은 **대조하기**로 적용한다. 동일 브랜치 조합은 안내하고, 메시지·SHA·작성자 검색과 대응 결과 필터는 즉시 적용한다. 기준 커밋 기간, 대상 탐색 범위와 예시 기준 SHA/시각을 표시한다.
- 대응 근거/변경 파일 상세와 후보 선택, 확인 대화상자를 거친 가상 연결/해제를 제공한다. 수동 대응 키는 `저장소 + 기준 브랜치 + 대상 브랜치 + 기준 SHA`이며 브랜치 조합별로 분리된다. 컴포넌트 메모리만 사용하므로 화면을 떠나거나 새로고침하면 초기화된다.
- PC는 표/근거 패널, 태블릿은 상세를 아래에 배치하고, 모바일은 세로 행과 상세 화면을 사용한다. 상세 닫기·Escape·목록 복귀 시 원래 행에 초점을 돌려주며, 필터로 행이 사라졌으면 검색 입력으로 돌려준다.
- 미리보기 상태 선택기로 연결 전·결과·불러오는 중·빈 결과·조회 실패·권한 부족·인증 만료를 확인한다. 검색 결과 없음은 빈 조회와 구분한다. 일시 오류에는 이전 결과/마지막 조회 정보와 재시도를 남기고 권한/인증 안내에서는 결과를 숨긴다.
- 기존 흰색 사이드바, IBM Plex Sans KR/Mono, 잉크 버튼과 절제된 상태 색상을 계승했다. 별도 전역 디자인 체계를 만들지 않았다.

## 검증 및 후속 범위

- 완료 검토에서 최종 판정은 `ship`이며 두 P2 수정(브랜치 조합별 수동 대응 분리, 사라진 행의 초점 복귀)을 해결했다. 이는 현재 가상 UI 단계의 판정이다.
- 검증 인계 기준: 전체 브라우저 52건과 단위 19건 통과 후 위 두 수정을 적용했으며, 수정 후 대상 브라우저 5건·TypeScript 검사·일반/데모 빌드가 통과했다. 전체 52건을 수정 후 다시 실행한 것으로 해석하지 않는다.
- 화면 증거: `.impeccable/review/commits/`의 `desktop`, `desktop-detail`, `desktop-candidate`, `disconnected`, `tablet`, `mobile`, `mobile-detail`, `error`, `empty`, `loading`, `denied`, `expired` PNG 12개. 디자인 탐지 결과는 `work/commit-ui-detect.json`의 `[]`이다(1회).
- 다음 단계는 실제 GitHub OAuth 연결과 저장소/브랜치/커밋 API 조회다. 권한·인증 만료·페이지 분할·조회 범위/기준 시점과 대응 근거를 실제 응답에 연결하고, 토큰 보관 및 수동 대응 저장 정책을 정한 뒤 별도로 구현·검증한다. 현재 OAuth/API 호출·토큰 저장·DB 변경·배포는 수행하지 않았다. 대응 결과는 서버 배포 여부를 뜻하지 않는다.
- 기존 문서 드리프트: `PRODUCT.md`는 내보내기를 후속 기능으로 기술하고 공개 데모를 조회 전용으로 설명한다. 현재 Excel 기능 및 이번 화면의 메모리 내 가상 대응 조작과 범위 설명이 달라 후속 정리가 필요하다. 이번 작업에서는 수정하지 않았다. `DESIGN.md` 부재도 새 시각 체계 승인으로 해석하지 않았다.
