# 등록·상세/수정·계정 화면 마무리 · 2026-10-30

## 범위와 디자인 판단

Impeccable의 `context --target src/features/requests/NewRequest.tsx`, layout 및 Operate 지침을 사용했다. 기존 구현과 인수 문서가 시각 기준이다. PRODUCT.md/ DESIGN.md가 없는 좁은 개선 작업이므로 새 디자인 체계나 초기화 인터뷰를 도입하지 않았다. 소개 페이지, 운영 Supabase 설정, 배포는 이번 범위에 포함하지 않는다.

- 등록: 왼쪽 요청 정보, 오른쪽 이미지·배포 설정·저장으로 묶는다. 하나의 form과 서버 계약을 유지한다. 모바일은 입력 순서대로 한 열로 쌓는다.
- 상세: 기본은 읽기 화면이다. 요청 내용은 줄바꿈을 유지하고, 빈 조치 요약은 실제 빈 상태로 표시한다. 고객사/작성자 정보는 읽기 전용이다.
- 수정: 명시적으로 들어가며 저장 성공 후 읽기로 복귀한다. 취소·이탈 확인, 실패 시 초안 보존, 독립 저장되는 활동·이미지의 구분을 제공한다.
- 모바일 배포 요약은 긴 본문보다 먼저 둔다. DOM도 같은 순서로 배치하고 데스크톱은 grid-area로 오른쪽 레일에 둔다. 시각 순서와 키보드 순서를 뒤집는 display:contents/order 조합을 대상 화면에서 제거했다.
- 계정: 실제 이름·이메일·역할·고객사 정보와 비밀번호 변경만 표시한다. 제공된 '계정 화면'은 초대/비밀번호 상태 모음이므로 프로필 전용 시안으로 오해하지 않고 기존 UI 규칙을 적용했다.

## 사용성 보완

- 수정 초안이 있으면 링크·브라우저 뒤로/앞으로·로그아웃·창 종료를 확인한다. React Router의 data hash router와 useBlocker를 사용한다. 주소의 `/#/...` 형식과 GitHub Pages 구성은 그대로 유지한다.
- 인증 콜백 처리 후 라우터를 초기화하며 StrictMode에서도 이력 리스너를 중복 생성하지 않는다.
- 이미지 준비 중에는 등록을 막고 준비 상태를 표시한다. 등록 실패 시 내용과 선택 이미지를 유지한다.
- 이름 저장은 공백 입력과 중복 제출을 막고, 저장 실패 시 입력을 유지한다. 배정이 없는 계정에는 관리자 문의 안내를 표시한다.
- 저장 성공 후 갱신 실패는 저장 실패와 구분하고, 초안/수정 모드를 유지한다.
