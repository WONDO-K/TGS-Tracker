# TGS Tracker UX/UI 검토 및 개선

작성일: 2026-10-29. 사용 스킬: design-taste-frontend, ponytail.

## 설계 목적과 판단

이 도구의 첫 질문은 “완료된 조치 중 운영에 아직 반영되지 않은 것은 무엇인가?”다. 기존 화면은 큰 짙은 사이드바, 네 개의 KPI 카드, 반복되는 작은 영문 라벨로 이 질문보다 대시보드 형식을 강조했다. 권한·DB·첨부 계약은 유지하고 정보 우선순위와 화면 구조를 바꿨다.

- 방향: **Achromatic ledger**, seed **591838824**. 후보 framed-sheet와 비교해 표·기록 중심의 반복 업무와 적은 메뉴에 적합해 선택했다. redraw 없음.
- 얼굴: 종이 장부 대신 테스트/운영의 두 환경을 나란히 비교하는 요청 장부. 중립적인 청회색 바탕, Geist와 한국어용 Noto Sans KR, 색은 운영 미반영 신호에 집중한다.
- 고유 요소: **테스트 → 운영** 사이에 남은 요청 수와 즉시 적용하는 필터. 마크도 두 단계 사이의 연결을 단순한 경로로 표현했다.
- 그래프·장식 이미지·새 UI 프레임워크는 추가하지 않았다.

| 화면 | 먼저 답할 질문 | 변경 |
|---|---|---|
| 진행 현황 | 어떤 요청이 어느 조치 단계에 있는가? | 칸반 유지, 각 카드에 테스트/운영 상태를 분리 표시 |
| 요청 목록 | 테스트 반영 후 운영에 빠진 요청은 무엇인가? | 날짜를 나란히 비교, 해당 요청의 운영 미반영과 제목에 작은 표시 |
| 요청 상세 | 무엇을 요청했고 어디까지 조치·반영했는가? | 운영 요약과 본문 구분, 모바일에서 운영 요약을 먼저 표시 |
| 고객사·사용자 관리 | 누구에게 어떤 고객사 접근을 줄 것인가? | 같은 글자·폼 규칙 적용, 관리자 표와 요청 목록의 모바일 스타일을 분리 |

## 동작 개선

- 넓은 사이드바를 제품명·주 메뉴·계정이 있는 상단 탐색으로 변경. 모바일·태블릿은 native details 메뉴로 접는다.
- 네 KPI 타일을 운영 미반영 강조와 세 보조 수치가 있는 한 줄 요약으로 통합. 수치는 현재 필터 결과에서 계산한다.
- 영문 대문자 라벨·장식 문구·색상 배경의 탐색 요소·카드 그림자 제거.
- 요청 제목/입력 14px, 표의 비교 데이터 13px, 보조 메타데이터 12px. 텍스트 대비와 tabular numerals 적용.
- 모바일 요청 표는 필드를 없애지 않고 제목·고객사·요청일·조치 상태·두 환경을 보여주는 목록으로 변환한다. 관리자 고객사 표는 표 구조를 유지한다.
- 필터 초기화 버튼 추가. 상세로 이동할 때 목록/칸반 경로와 필터를 history state로 보존해 복귀 시 그대로 돌아간다.
- 긴 계정명은 상단에서 말줄임해 탐색 폭을 지킨다.

검사 대상은 `npm run build:demo`로 생성하고 `vite preview`로 제공한 실제 배포 빌드다. 기존 16개 단위/SQL 검증, 6개 브라우저 검증과 타입 검사·실무/데모 빌드를 실행한다. 새 브라우저 검증은 모바일 메뉴, 필터 초기화, 상세에서 필터를 유지한 복귀, 관리자 모바일 표를 포함한다. 외부 Auth/Storage HTTP 경계를 대체하는 기존 테스트의 범위는 유지한다.

### 남겨둔 경고와 이유

- 작은 글씨 비율: 날짜·작성자·환경 이름 같은 보조 메타데이터는 12px로 유지한다. 요청 제목·필드·주 데이터는 13~14px 이상이며 11px 미만은 없다.
- 칸반의 ragged-row: 각 단계의 실제 요청 수가 다르다. 요청 수를 맞추거나 빈 높이를 늘리면 진행 현황을 왜곡하므로 각 열은 실제 콘텐츠 높이로 표시한다.
- 상세의 ragged-row: 긴 요청 편집 폼과 짧은 활동 기록은 별개의 흐름이다. 우측 기록을 폼 높이까지 늘리지 않고 상단 정렬하며 모바일에서는 위아래로 배치한다.
- lint의 section-label: 제목 위 장식 라벨이 아니라 실제 첨부/담당 고객사 입력 영역의 필드 라벨이다.
- lint의 padStart: 번호 장식이 아니라 가상 데이터의 날짜/시간 문자열 형식을 위한 것이다.

검사 예외를 숨기는 `--allow` 옵션은 사용하지 않았다.
