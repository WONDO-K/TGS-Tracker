# TGS Tracker UI 디자인 인수 문서 (Codex용)

이 문서는 `고객사 요청·조치·배포 관리 시스템 설계서 v1.2`를 구현할 때 UI를 어떻게 만들지 정리한 것이다. 기능·데이터·권한 규칙은 설계서가 우선이고, 이 문서는 **시각 스타일과 화면 구성**만 정한다. 디자인 시안의 고객사명·사용자명·요청 제목은 모두 가상 데이터다.

스택은 설계서대로 React + Vite + TypeScript, React Router(HashRouter), 일반 CSS다. 별도 UI 라이브러리·Tailwind는 쓰지 않고 아래 토큰을 CSS 변수로 정의해 사용한다.

---

## 1. 디자인 방향

- 업무용 도구답게 차분하고 정돈된 밝은 톤. 그라데이션, 이모지, 왼쪽 선만 있는 카드, 과한 장식은 쓰지 않는다.
- **색은 의미가 있을 때만 쓴다.** 상태 4색과 경고 코랄 외에는 무채색(잉크·회색)으로 구성한다.
- 모서리는 둥글게(12~24px), 그림자는 옅은 두 겹.
- 모든 클릭 영역은 최소 **44px**. 버튼은 `<button>`, 링크는 `<a href>`, 입력은 `<label>`과 연결한다. div에 클릭 이벤트를 달지 않는다.

## 3. 레이아웃

- 데스크톱: 왼쪽 사이드바 **236px**(흰색, 오른쪽 `--line` 테두리) + 본문(패딩 `30px 36px`).
- 사이드바: 로고 → "업무"(진행 현황, 요청 목록) → "관리자"(고객사 관리, 사용자 관리; **관리자에게만 표시**) → 하단 사용자 정보. 현재 메뉴는 `--hover` 배경 + 600 굵기.
- 보드: 4열 그리드, 열 간격 14px, 카드 간격 10px.
- 상세/등록/수정: 본문 + 오른쪽 380~420px 패널 2단.
- **1000px 이하**: 사이드바를 숨기고 하단 탭바(현황 / 목록 / + 요청 등록 / 메뉴)로 전환, 보드는 열 대신 상태 탭 + 카드 한 줄 목록. 표는 가로 스크롤 컨테이너 안에 둔다.

## 5. 컴포넌트 규칙

- **요청 카드**: 흰 배경, 반경 16, `--shadow-card`. 윗줄 `#번호`(mono, `--text-4`) + 고객사 칩, 제목(600, 14.5px, 최대 2~3줄), 작성자 이니셜 아바타 + 이름 + 날짜 + "첨부 N", 맨 아래 **배포 진행선**.
- **배포 진행선**: `TEST ●─○ PROD` + 오른쪽 알약. 반영된 단계는 `--ink`로 채운 점, 미반영은 `#B4BBC8` 테두리의 빈 점. 알약: 테스트 미반영(회색), 운영 미반영(코랄), 운영 반영 `MM.DD`(완료 초록), 배포 불필요(회색, 진행선 없이 알약만).
- **배포 필터 토글**: 트랙(`--track`, 반경 14) 안에 항목들, 선택 항목은 흰 알약 + 옅은 그림자. "테스트 반영·운영 미반영 N"만 코랄 글자 + 굵게.
- **경고 요약 카드**(보드 상단): 코랄 `N` 박스(60px, 반경 18) + 설명 + "바로 보기 →". **필터 건수는 같은 필터의 DB 집계**이고 완료 열 포함이다.
- **상태 분포 막대**: 상태 색 4조각 막대 + 범례.
- **상태 알약**: 점 + 이름, 상태별 옅은 배경·글자색.
- **상태 선택 버튼**(상세): 2×2 그리드, 선택 시 상태 색 테두리 1px. 드래그 없이 클릭으로 이동 가능해야 한다.
- **표**: 헤더 12px `--text-4` 배경 `#FAFBFC`, 행 높이 56~60px, 구분선 `#F0F2F5`, 호버 `#FAFBFD`.
- **입력창**: 높이 48~50, 반경 14, 테두리 `--input-border`, 배경 `--input-bg`. 오류 시 테두리 `--warn` + 아래 12px 코랄 문구.
- **스위치**: 44×26, 켜짐 `--ink`. 실제 `<input type="checkbox">`를 숨겨 쓰고 포커스 링을 유지한다.
- **버튼**: 주(`--ink` 배경, 흰 글자, `--shadow-cta`), 보조(흰 배경 + 테두리), 위험(`--warn` 배경). 비활성은 `opacity .35`와 `cursor:not-allowed`, `aria-disabled` 표시.
- **모달**: 폭 400, 반경 24, 상단 48px 아이콘 타일(파랑·코랄·앰버·잉크), 제목 20px, 본문 14px, 하단 버튼 2개(취소 / 실행). 위험 작업만 실행 버튼을 코랄로. 배경은 어두운 오버레이.
- **타임라인/활동 기록**: 유형 태그(시스템=잉크, 조치=파랑 옅은 배경, 메모=회색).
- **파일 항목**(첨부): 48px 썸네일 + 이름 + 상태 문구(준비됨=초록, 업로드 중=진행 막대, 실패=코랄 테두리 + "재시도/취소").
- **배너**: 보관된 요청(회색 + 잠금 아이콘 + 관리자에게 "복원" 버튼), 사용 중지 고객사(앰버), 데모(파랑).

## 7. 반드시 지킬 동작 (설계서 반영)

1. **완료 ≠ 운영 반영.** 완료 열의 요청도 "테스트 반영·운영 미반영" 필터에 포함된다. 필터 조건: `requires_deployment=true AND test_deployed_at IS NOT NULL AND production_deployed_at IS NULL AND archived_at IS NULL`.
2. 보드 열 합계와 상단 경고 건수는 **현재 불러온 카드 수가 아니라 DB 집계**다. 각 열은 30건부터 불러오고 "더 보기"로 추가한다.
3. 상태 이동은 DB 성공 후 확정한다. 실패·충돌 시 이전 상태를 유지하고 오류를 안내한다.
4. 폼은 저장이 성공하기 전에 입력을 지우거나 닫지 않는다. 저장 충돌 시 입력을 보존하고 "내 입력 복사 / 최신 내용 불러오기"를 제공한다.
5. 반영 시각은 미래를 허용하지 않고, 한국 시간으로 표시한다. 배포 불필요로 바꾸면 확인 후 두 반영일을 비운다.
6. 이미지: JPEG/PNG/WebP, 원본 10MB·저장 2MB 이하, 요청당 5장, 브라우저에서 긴 변 1920px로 축소 후 미리보기. 본문 저장 성공과 이미지 실패를 구분해 표시한다.
7. 사용 중지 고객사·보관 요청은 읽기 전용이다. 수정 컨트롤은 숨기지 말고 **비활성 + 이유 배너**로 보여 준다.
8. 권한 없음·존재하지 않음 문구는 같게 쓴다("요청이 없거나 열람 권한이 없습니다"). 다른 고객사의 존재를 드러내지 않는다.
9. 관리자 메뉴는 UI에서 숨기되 **서버·DB 검증이 실제 권한을 결정한다.** 마지막 활성 관리자는 강등·차단할 수 없다.
10. 관리자 승격 확인 모달은 범위(전체 고객사 접근)를 명시하고 체크박스에 동의해야 버튼이 활성화된다.
11. 데모 빌드(`VITE_APP_MODE=demo`)는 조회만 제공하고 편집·관리·초대 UI를 제거한다.

## 8. 시안과 구현의 차이 (주의)

- 시안은 **정적 마크업**이라 실제 상호작용, 입력 검증, 로딩 흐름은 없다. 시안의 오류 상태는 대표 예시다.
- 비밀번호 규칙("8자 이상"), 초대 재발송 간격(60초)은 설계서에 수치가 없어 가정한 값이다. 확정되면 바꾼다.
- 시안의 날짜·건수·이름은 가상이다. 요청 제목, 고객사명 등을 실제 데이터로 하드코딩하지 않는다.
- 시안의 표는 10건만 보여 준다. 구현은 페이지당 30건이다.
- 색상값 중 일부는 화면마다 한두 단계 차이가 있을 수 있다. **이 문서의 토큰을 기준으로 통일**한다.

## 9. 구현 순서 제안

1. 토큰을 `src/styles/tokens.css`에 CSS 변수로 정의하고 글꼴을 불러온다.
2. 공통 컴포넌트(`Button`, `Input`, `Switch`, `Pill`, `Card`, `Modal`, `Banner`, `Sidebar`)를 먼저 만든다.
3. 진행 현황 보드와 요청 목록(핵심 필터·건수)을 만든 뒤, 상세·등록·수정으로 확장한다.
4. 관리자 화면과 모달을 만든다.
5. 로딩·빈 상태·오류 상태와 모바일 레이아웃을 마지막에 맞춘다.
