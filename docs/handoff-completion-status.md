# HTML 시안 대조 및 후속 작업 현황 · 2026-10-29

이 기록은 `handoff-ui-implementation.md`의 첫 적용 이후 작업을 구분한다. HTML은 21개 정적 시안을 포함한다. “기능 연결”은 기존 RLS/RPC에 연결한 실제 UI라는 뜻이며, 실제 운영 Supabase/SMTP 연동 완료를 뜻하지 않는다. 동일 기능의 화면·상태·모달을 각각 독립 경로로 만들지는 않는다.

## 이번 작업 순서와 결과

1. 전체 시안 대조: 아래 표로 관리한다.
2. 로그인·관리자: 시안의 실제 배치와 폼·초대·권한 설정 흐름을 보완했다.
3. 예외 처리: 초안 복사/복사 차단 시 수동 복사, 운영 반영 저장 확인, 보관/복원, 인증 만료 복구, 초대 실패·중복 이메일 안내·재발송 제한, 마지막 관리자 보호, 404 복귀를 보완했다.
4. 검증: 실제 포인터 드래그 성공/실패, 권한 부분 저장 재시도, 초안 보존과 관리자 초대 실패를 브라우저에서 확인한다. 실제 클라우드 자격 증명은 이번 작업 범위에서 사용하지 않는다.

## UX 및 구현 결정

- DB/RLS/RPC·GitHub Pages 설정은 변경하지 않는다. 새 의존성을 추가하지 않는다.
- 기존 10자 비밀번호 정책을 유지한다. 실제 정책과 무관한 8자 예시를 복제하지 않는다.
- 운영 반영은 폼의 시각 입력 + 저장 확인으로 구현한다. 진행 상태를 완료로 바꿔도 운영 반영일은 자동 기록하지 않는다.
- 관리자 권한 저장과 고객사 배정은 기존 두 RPC다. 첫 요청만 성공할 수 있어 부분 실패를 설명하고 입력을 보존한다. 재시도에서는 원하는 접근 상태를 다시 저장해 되돌린 권한이 서버에도 적용되도록 한다. 서버의 마지막 관리자 보호는 계속 최종 기준이다.
- 데모 로그인 화면은 실제 계정 입력 폼을 제공하지 않고, 관리자 메뉴·쓰기 기능을 계속 숨긴다.
- 정적 시안을 모두 옮겼다고 보고하지 않는다. 기능 통합과 시각적 세부 차이를 위 표에서 구분한다.

## 이번 작업의 검증 결과

- DB/단위 테스트 16개 통과 (`npm test`).
- 브라우저 테스트 20개 통과 (`npx playwright test`). 실제 React·Supabase SDK를 실행하며 외부 HTTP 경계만 가상 응답으로 대체한다.
- 실무/데모 타입 검사 및 빌드 통과. 실무 번들에는 500kB 초과 경고가 있으며 실패는 아니다. 현재 작은 앱 규모에서는 새 청크 구조를 도입하지 않았다.
- 로그인·고객사·사용자·상세 화면을 1440/768/390px로 캡처하고 페이지 가로 넘침이 없음을 확인했다. 관리자 표는 표 내부 가로 스크롤을 허용한다. 캡처는 `.taste-skill/completion/`에 보관한다.
- 리뷰에서 찾은 권한 부분 저장 후 재시도의 잘못된 접근 상태 잔존과 인증 오류의 재노출을 수정했다. 두 경우 모두 회귀 테스트가 포함된다.
- 서버 접속·초대 메일 발송·실제 비공개 이미지 저장은 운영 Supabase 설정 후 별도 검증이 필요하다.
- 정적 실무 빌드 로그인 inspector: 0 FAIL, 1 WARN. 여백 경고는 로그인 왼쪽 소개/오른쪽 최대 400px 폼의 의도된 분할 구성으로 유지했다. 폼을 늘려 입력 줄이 길어지게 하지 않았다.

화면 평가 ROUND 3: 첫 시선은 로그인 폼과 제품 설명, 관리자 화면은 사용자 표와 선택한 권한 설정이다. 제품의 핵심은 “업무 완료와 운영 반영을 따로 확인”이다. 기존 카드형 관리자 화면에서 표+편집 패널로 바꾸고, 모바일은 전체 페이지 넘침 없이 표 내부에서만 이동한다. design 8 / usability 8 / creativity 7 / content 8 → 7.8. 가장 큰 남은 시각 차이는 등록·수정·계정의 세부 화면 구성으로, 위 후속 순서에서 처리한다.
